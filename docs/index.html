M365 + Okta Lifecycle Toolkit

PowerShell scripts that onboard and offboard users across Microsoft Entra ID, Exchange Online, Intune and Okta from a CSV, with a dry run before every change and a log of every step.

View on GitHub Try the dry run

Why

Most access problems start at onboarding and offboarding: new hires waiting for apps on day one, and people who have left still holding access weeks later. These scripts run the same steps, in the same order, for every user, and keep a record of what was done.

What it does

Onboarding

  1. Map role to groups and licenses
  2. Build a clean, unique UPN
  3. Create the Entra ID user with a temporary password
  4. Set the manager
  5. Add role groups (group-based licensing)
  6. Create the Okta user and add Okta groups
  7. Show a one-time hand-off table

Offboarding

  1. Save group memberships for audit
  2. Block sign-in and reset the password
  3. Revoke sessions
  4. Convert the mailbox to shared, add an auto-reply
  5. Remove groups, then licenses
  6. Retire Intune devices
  7. Clear Okta sessions and deactivate the user

Design choices

  • Dry run first. Every tenant change goes through one function, so a dry run can't change anything.
  • Order matters. Sign-in is blocked and sessions revoked first; licenses come off only after the mailbox is shared.
  • Keep going on errors. A failed step is logged in red and the rest of the offboarding still runs.
  • No secrets on disk. Okta tokens come from environment variables; temporary passwords are shown once and never logged.
